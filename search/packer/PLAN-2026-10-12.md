## Diagnosis
* Since 10-05: 136 record events at n <= 324 (59 n).  Ours: 7 events, 1.5 % of the gain; we hold 3 of the 59 moved n.
  All 10 of our events (incl. n > 324) are perturbation / removal + explorer.
* ~77 % of the gain at n <= 324 came from families we do not have: rectangle-library composition (41 events, 0.171),
  LLM-evolved constructors (18, 0.173), removal / insertion n +- k (23, 0.105); at n > 324 L-border growth (0.289).
  Perturbation / polish: 51 events but 4.5 % of the gain (Couzo, often with our fq / exactsolve).
* Our cost per record event rose 25 -> 35 -> 63 -> 180 CPU-h (PACKER ledger).  Plain chain / explorer compute is
  past its useful point on the current frontier.  The n = 110 census answered its questions (C05, C13 / X16).

## Yardstick (replaces the 110 battery as the gate for new operators)
Event benchmark: inputs = everything public at a cutoff T; success = any certified packing below frontier(T) for an n
(gain >= 1e-8 after `candidate.py`); secondary = fraction of the later posted gain recovered.  Run on **all** n: on n
nobody has improved since T, success is a live record (register check, then submit).  Batch cutoffs: 10-05 register
(21 n moved by 10-07), 10-08 00:00 (23), 10-09 20:00 (20), 10-11 05:00 (15), 10-12 04:00 (14).
Each operator first passes a positive control (one named event, CPU-hours at most), then runs across a batch cutoff.
Live records found in a benchmark run don't steer adoption more than any other success.

1. **fq: rectangle container + rounded squares** (S).  Wall x <= s + dx, y <= s + dy; rounding r = inner half-side
   0.5 - r and margin r on every separator and wall (still linear in the lifted variables).  `--round` schedule with
   a dwell at intermediate r (lit §6: rounding picks the phase), box fixed.
   Control: soft-to-rigid V-merge on 241 (Couzo house) and 211 (our de Winter optimum), events B in EVENTS.
2. **Rectangle library** (M): best h(m, d) for m squares in (h + d) x h, d = 0..4: every store packing's corner crops
   re-optimised as rectangles with fq (+ explorer in the rectangle), small m from scratch incl. symmetric starts.
   A 2-D frontier table others can use.  Controls: 129 (cut from 302's library piece), 232.
3. **Composer v2 = recursive partition DP** (M; Birgin-Lobato-Morabito pallet loading: raster points, 5-block and
   L-splits) over library pieces + exact axis fill (needs NEEDS 2: soft fill / pocket candidates) + interlock /
   corner overlap + seam polish (fq, then rounding re-hardening of the seam).  A DP miss at n = no rectangle-edged
   composition beats the frontier there.  Controls: 176, 232, #528's 175 / 264.
4. **Insertion / removal that doesn't jam** (S-M): dynamic-lattice insertion (lit §5: probe-square sites against
   tilted neighbours, worst square -> best site, relax); removal n + k -> n with k up to ~5.  First a cheap diagnosis:

6. **Constructors** (S): symmetric-subspace starts (84 / 305 best-known are exactly symmetric, diagonal mirror most

7. **Fresh-packing pass** (S, standing, low compute): every newly posted packing -> store -> short explorer + polish
