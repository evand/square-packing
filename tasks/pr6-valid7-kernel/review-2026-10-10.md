- The **generated** files (R?????.lean, Face.lean, Main.lean) are a different matter (see §3).
  - Emitted roots add `set_option maxHeartbeats 0` and `noncomputable section` (emit_v7.py:80-82).
  - Leaf names (`c['name']`) and every literal come from the pickles and are pasted verbatim into

  - A malicious pickle can therefore inject arbitrary Lean commands (`#eval` with IO, `initialize`,

The region and symmetry argument **[read]**:

- `CovT` (ExTree.lean:32-40): every pose with c in the box, u0/R < u ≤ u1/R, **u² + 2u ≤ 1**, and
  `sq c (2 arctan u) 1 ⊆ box (Mq/D)` captures mass ≥ W.
- `cover_of_tree` (ExTree.lean:278-420) does the rest:
  - It derives D4 invariance of `mcoverP`'s measure from kernel-decided data checks (`d4Check`,
    `segD4Check`, `rectD4Check`) and proves it in Lean (`M.d4InvM`, ~ll. 335-385).
  - It applies **main's** `d4_reduction_measure` (l. 397) to reduce to c ∈ [0, m/2]², θ ∈ [0, π/4].
  - It writes θ = 2 arctan u with 0 ≤ u ≤ 1/2 (`exists_u_of_theta45`).
  - It sends u = 0 to the face (`hcov0`) and u > 0 to the tree (`hcov`).
- So the symmetry reduction is fully in-kernel.  `SYM` leaves are sound because the 45° cap is part of
  `CovT` (`CovT.of_sym`, l. 91).
- The final statement is main's unchanged `Bentz.Valid7` (Bentz.lean:65): every pose in [0,7]².
  `ValidTilt7` (ValidSplit7.lean:64; region c ∈ [0,7/2]², u > 0, u² + 2u ≤ 1) is then a trivial
  special case.  **The region is therefore more than what ValidTilt7 needs**: the PR proves all of
  Valid7 directly.

Can a bad certificate make Main prove something weaker?

- **Through the logic, no [read].**  `root_XXXXX` are used as arguments of `CovT.split*`, so each must
  have exactly (definitionally) the `CovT` type for its box, over `tsegs`/`trects`.
- The conclusion of `cover_of_tree` is about `mcoverP ...`'s measure.  Bridge proves that measure
  equal to main's `box7Cover.measure`.  The leaf checker, the tree combinators and the encoding are all
  proved (`*_sound`, `of_exact`), not trusted.
- So the certificates are data, and correctness of Python, pickles, mirrors and generators is
  irrelevant to soundness, **provided the generated .lean files contain only the expected kinds of
  commands**.
- **Caveat 1, name shadowing.**  `theorem valid7 : Bentz.Valid7` is elaborated inside
  `SquarePacking.LemmaELeaf`.  If any imported root module (e.g. via an injected leaf name) declared
  `SquarePacking.LemmaELeaf.Bentz.Valid7`, Lean's name resolution would prefer it, and Main would
  "prove" the fake.  `#print axioms` would not show this.
  - Defence: an audit file stating
    `example : SquarePacking.Bentz.Valid7 := SquarePacking.LemmaELeaf.valid7` (fully qualified,
    outside any namespace).
  - Plus a strict grep of every generated file.
- **Caveat 2, environment tampering.**  `set_option debug.skipKernelTC`, custom elaborators, or a
  macro that overrides `#print axioms` output would also escape a `#print axioms` check.
  - Defences: an allowlist grep of generated sources.  Lines may only be `import`, `namespace`, `end`,
    `open`, `noncomputable section`, `set_option maxRecDepth/maxHeartbeats`, `def`, `theorem`,
    continuation lines, and comments.
  - Leaf names must match `[A-Za-z0-9_]+`, and there must be no `#`, `@[`, `macro`, `syntax`,
    `notation`, `instance`, `axiom`, `elab`, `initialize`, `debug`, or the tokens `Bentz`/`Valid`
    inside root modules.
  - Ideally also lean4checker replay, at least on a sample.

## 4. Bridge (V7/Bridge.lean, 97 lines) [read]

`box7Cover_eq_mcoverP : Bentz.box7Cover.measure = (mcoverP 5 10^12 PTree.leaf segsT trects).measure`
(l. 40).  The proof:

- **Points:** ∅ = ∅.
- **Segments:** a bijection `j ↦ segNorm (boxSegs.get j)` onto `segsT.toList = tsegs`.
  - Kernel-decided: `boxSegs.map segNorm` is Nodup (l. 21) and the two inclusions (l. 24, 28).
  - Weights are preserved; `segMeasure` is symmetric under endpoint swap (`segMeasure_segNorm`).
- **Polygon:** `convPoly 5 boxPolyVerts = rectSet 5 (9,9,26,26,_)`, using main's `convPoly_box`, with
  volume 289/25 and density 1 matching `boxPolyW`.

It is a single equation whose left side is main's definition, closed by the kernel, so it is sound if
it compiles.  I see no gap.  It doesn't depend on any other PR definition being "right": `mcoverP`
only has to be whatever `cover_of_tree` talks about, and it is.

## 5. Checker architecture

The pose tree's leaves are `EMPTY`, `SYM`, `AXIS` (u1 = 0), degenerate, `LEB` (Lemma U),
`CAP` (Lemma K, CapK.lean) and `EXACT` (Lemma E, LemmaELeaf/LemmaELeafX).  For an EXACT leaf over a
centre box and angle bin:

- The bound `fE(c) = Σ_claimed segments κ·max(0, min of affine chord/segment-end forms) +
  Σ_Lebesgue ρ(1 − ĝ_x − ĝ_y)` (with inclusion–exclusion corners E″ and tangent caps) is proved
  concave on each cell of a line arrangement (ChordE, LemmaE).
- A concave function on a bounded polygon attains its minimum at a vertex (PolyMin, an elementary
  proof).
- For every pair of lines (polynomial in u = tan(θ/2), as scaled lines `SL` / rational functions `RF`
  with denominators made of powers of Δ, 1−u², 2u, 1+u²), the certificate shows on sub-bins one of:
  - the pair is parallel;
  - or the vertex lies outside the region;
  - or `fE(vertex) ≥ W`.
  The last is checked via chosen chord ends and `ĝ` regimes (LemmaEVert).
- Sign tests are Bernstein in pure integer arithmetic (BernsteinZ), in Kronecker-packed form: a
  polynomial is one big integer, and the check is a digit-mask test (KArith, KBern, LemmaEK).  The
  `X` variants bound all segment-alternative combinations by digit-wise row minima (RowMinK, LemmaEKM).
- Certificates are decoded from compact ℕ lists inside Lean (LemmaEDec, untrusted decoding).
- The θ = 0 face is Lemma Z: bilinear on cells, so corner evaluation suffices (LemmaZ.lean).

The top-level theorem `cover_of_tree` concludes
`∀ c θ, sq c θ 1 ⊆ box (Mq/D) → 1 ≤ (mcoverP ...).measure (sq c θ 1)`.  That is stated with main's
`sq`, `box`, `MixedCover.measure` and `d4_reduction_measure`, and tied to `box7Cover` by Bridge.

**[author]** That every module compiles, and the reported times and memory.

## 6. Overlap with main and structural suggestions

- **Face / Lemma Z / D4 are duplicated.**  Main already has `validAxis7` (ValidSplit7.lean:80, Lemma Z
  via `axisOKP`), `d4_box7`, and `valid7_of_tilt` (l. 87: `ValidTilt7 → Valid7`).
  - The PR's region at u > 0 (c ∈ [0, 7/2]², 0 < u ≤ 1/2, u² + 2u ≤ 1) contains ValidTilt7's region
    (c ∈ [0, 7/2]², u > 0, u² + 2u ≤ 1).
  - So **`validTilt7` can be proved directly from `v7_tree` + Bridge**, plus a small lemma relating
    `ptMass + segMass + rectMass` to `measure`; `cover_of_tree`'s `hmass` already contains it.
  - Then `bentz := bentz_of_validTilt7 validTilt7` from main.
  - This **drops Face.lean (~49 GB, ~8 min), LemmaZ.lean (610 lines) and the PR's own D4 invariance
    proof**.  The PR author has already offered to reuse `validAxis7`.
- **LEB/CAP leaves:** main's `LebMass` (Lemmas U and K, with `LebMass7` checking all 689 LEB + 374
  CAP leaves) duplicates the PR's `CovT.of_leb` and `CapK`.  A conversion `ZMTreeM.CovT →
  LebMass.CovT` (or the reverse) would let one tree layer serve both.  Not required for soundness.
- **Naming:**
  - Rename `ZMTreeM.CovT` (e.g. `CovTE`).
  - Re-export the final results as `Bentz.validTilt7` / `Bentz.valid7` rather than
    `LemmaELeaf.*`.
  - Make the checker opt-in instead of adding 16 imports to `Sqpack.lean`.
  - `LemmaELeafX` is a copy of `LemmaELeaf` with `X` suffixes; it could be factored.
- **Doc inconsistencies:**
  - Timings differ: the PR body gives Bridge 2m13s/19 GB, Face 7m39s/49 GB, Main 1m24s/58 GB,
    ~7,000 process-hours.  VALID7.md gives Face 9 min/47 GB, Bridge 7 min/24 GB, Main 2m17s/58 GB,
    "roughly 10^4 CPU-hours".
  - VALID7.md step 2's X/non-X emission split is per `v7_xroots.txt` (2,612 roots).  Either form is
    sound; the split only affects cost.
