# Record-event corpus, 2026-10-05 .. 2026-10-13 00:42 UTC (built 10-12; read-only)

Purpose: which *operators* produced the record improvements since the 10-05 register, so that we can (1) see which
techniques we lack and (2) benchmark our tools by whether they recover each event from what was public before it.

**Sources.** jlevy/squares issues #375-#575 (bodies + author comments; `gh issue view`), the store (`pk.py`, read-only
sqlite queries of `frontier` / `sighting`), commit dates of finders' repos (`gh api`, read-only), PACKER.md (hunt1 on),
notes/refresh-2026-10-11.md, REVIEW-2026-10-11.md §4.  Build scripts and the machine-readable list (`events.json`) were in the
session scratchpad; not kept (rebuild: the claim list is the table below).

**Method.**
- Every side claimed in an issue (or a finder's repo when there is no issue: Mishapolk 132 / 267, Couzo `f311f08` 175,
  Ostashev's unrequested 176, our unposted big1 375) is one claim, timed by issue post (repo publish time for Xu: 10-08
  00:03; comment time for Couzo's #460 update).
- Claims are processed in time order per n against a running frontier.  It starts at the **10-05 register**
  (`search/exact/batch/inputs/n-*.txt`, the same frozen snapshot as `runs/timetravel/truth.json`); for n > 324 it starts
  at the grid or at Göbel's 376 / Couzo's 375 (`2d32a6e`, 10-08), the best we hold from before.
- **Old best = frontier(T)**: the best public side just before the event, counting register, open issues and finders'
  repos, not the register alone.  A claim is a **record event** if gain = old − new ≥ 1e-8.  0 < gain < 1e-8 counts as
  precision (listed below, not in the table).  A claim at or above frontier(T) is stale (listed below).
- Family codes: A rectangle-library composition / graft (SQUISH grafts and Mondrian, Ostashev's rectangle library);
  B soft-to-rigid re-hardening; C corridor / grain-boundary basin hopping; D L-border growth; E wedge-cut growth;
  F removal from n+k; F/G removal or insertion from n±k of the finder's *unfiled* packing; H perturbation / polish of an
  existing packing (whose: see parent); I exact patch construction; J LLM-evolved constructor; K other (Ostashev's
  explicit V-band + IP corner-block constructor; Rio Calle's from-scratch GPU search).
- `arr`: new = a different arrangement (the finder's statement or a different construction); near = a nearby, different
  basin reached by basin hopping or explorer moves; ref = same arrangement, polished.
- `parent public before?`: Y; N (unfiled); partial (some pieces public); Y* (the parent was posted in the same issue);
  "src released w/ issue" (SQUISH put its source pieces in `sources/` in the same commit); "-" (no parent).
- Caveats.  Provenance is as the finder states it (socially verified).  Sides are the issue's 12-15 digit values, which
  is enough at a 1e-8 event threshold.  Nothing here was re-verified by us except what the store already holds.
  Mishapolk's 132 / 267 have no stated lineage.  Couzo's n > 324 L-border packings were in his repo (`3ef7634`, 10-10,
  and earlier) before #506.  Their first appearance is dated by #506, and the old best is the grid.
