# Packer review, 2026-10-11

Read-only review of `search/packer/` + `search/exact/` before the next moderate/large compute run (Evan's questions: is the
code composed well; one pipeline or several; do we know what we tried and why it failed; do we know how we know; what to fix
first).  Four parallel reviews (architecture, methods ledger from all of PACKER.md, epistemics/provenance audit, external
code + literature), synthesised; the concrete bug and data claims below were re-checked by hand on 10-11.
"L###" = line in `PACKER.md` as of 10-11.  [V] = checked in code/data, [D] = from docs, [I] = inference.

## Summary

The core instruments are good (fq, exactsolve + jam MILP, the frozen-proposal bench `pk/corpus.py`).  Around them: two
pipelines instead of one, ~7 definitions of "same basin", 3 of "certified", thin run provenance, and several TODO
"Decisions" resting on one replicate at n = 110 with screening-level (mostly unconverged) novelty.

## 1. Composition: six routes, not one pipeline

| route | path | quench |
|---|---|---|
| R1 chain / hunts (hunt1, h2, hunt3) | `chain.py` seeds (`hop.quench`) -> `explore.py` subprocess -> archive -> manual exactsolve / verify_cert / descend / dilate_cert -> `candidates/`; store import manual | `hop.quench` (fq process + temp files per call) |
| R2 lineage / insert110 | `explore.py --novel-ref` -> `census_certify.py` -> `descend_census.py` | same |
| R3 bench / battery / crossing | `pk/corpus.py`, `pk/battery.py` -> `pk.pipeline.evaluate` -> `pk.engine` | `fq serve` |
| R4 census | `census_certify.py` (one representative per 1e-9 key) + `descend_census.py` | exactsolve |
| R5 Mondrian | store kingbird rows -> `gen` fill -> `pk.engine.FQ` -> optional `explore.py` subprocess (own copy of hunt flags) | `fq serve` |
| R6 certificates | exactsolve -> verify_cert / verify_cert2 -> bundles | — |

`pk.engine` / `pk.pipeline` serve only R3 and R5; every production hunt goes through `explore.py` + `hop.quench`
(DESIGN step 5, explorer v2 on pk, not done).  Two move registries (`explore.MOVES`, `pk.moves.MOVES`); explorer recipe
copied in `chain.py:170`, `mondrian.py:823`, `lineage_reach.py:84`, `insert110.py:140` with different reward settings.

**Identity ("same basin"), seven definitions [V]:** explorer |Δs| < 2e-9; chain library > 1e-9; store packing D4 hash
(positions rounded 1e-6, side 1e-9: rounding, so boundary copies split); `basin` table `f'{s:.9f}'` with
`UNIQUE(n, key)`; census exact S prefix [:23]; `known110_all` 5e-9; fq contact fingerprint.  Unconverged copies sit up to
8.5e-4 above their minimum (L1178), so every side-key count is a key count, not a minimum count.

**"Certified", three meanings:** (a) store / basin / exact.json: S_exact + cert_valid + second order OK **or
"inconclusive"** (`census_exact.py:38-40`; docstring line 9 says inconclusive -> unresolved; flag lost on store import,
`sources.py:207`); (b) records: exact optimum + verify_cert + verify_cert2; (c) s(343) 10-10: dilation certificate of a
point that is not a local minimum.

**Jam tests, five:** fq flip search; slp2/inc MILP; rigid.py one-axis LP (false jams); exactsolve max-support LP + vv MILP
("not jammed" only if dS < −1e-6, `exactsolve.py:843-848`: [I] points with −1e-6 < dS < 0 go on to KKT, check); descend.py
(thr 1e-6 default, 1e-9 in descend_census).  Matching distance, three variants (`cross.align` scales mate to parent,
`rediscover.distance` the other way, rattler-masked in lineage_reach).

**Confirmed bugs / traps [V]:**
- `pk/pipeline.Policy.same = 1e-6`: the screen-return shortcut c110a showed loses ~half the new basins; explore.py moved to 0, pk did not.
- `explore.report` hard-codes k = ceil(sqrt(110)) and "the known 48" (explore.py:348-353): end-of-run summary wrong for n ≠ 110.
- `explore.py` ANNEAL = `target-dev/release/anneal` (10-08) vs `pk/anneal.py` `target/release` (10-09); `explore.mv_melt` discards the anneal's returned side (`pk.moves.melt` uses it).
- `explore.work` and `mv_melt` `mkdtemp()` without cleanup: **786,728 `tmp*` dirs in /tmp**, disk 92 % full.
- `pk.engine.FQ.quench(timeout=)` accepted, never used: a hung `fq serve` blocks forever.
- fq applies `--loosen` (default 1.02) even with `--no-alm` (fq.rs:1347-1357); all callers pass 1.0 today.
- `mcmin.write_deg` doesn't cast to float (numpy-2 `np.float64(...)` gotcha, NEEDS gotchas).
- `RANK` lets `certified` overwrite `not-min` silently (store.py:18,74); `import_runs` uses `check=False` (no pen for run rows).
- `pk.py frontier` "register" column includes closed issues (`pending=0`, sources.py:166); `best:N` = lowest feasible row incl. raw / not-min / grid rows.
- Four register copies (`exact/batch/inputs` frozen 10-05 = still the default for chain/hop; `inputs_live` + `regnow`; `runs/jlevy`; third-party clone).
- Store: 0-byte decoy `runs/store.sqlite` at the repo root; real store `search/packer/runs/store.sqlite` (1.03 GB).  First backup 10-11 (TODO).
- No run provenance: explore / chain / battery (meta = arm, n, minutes) / corpus / lineage / insert110 record no argv, commit, binary hash; only `pk/jobs.py` records the commit.  Battery / corpus finals never reach the `packing` table.  Explorer `proposals.jsonl`: no move params, per-proposal seed, child id.  CPU = wall x procs on a loaded machine.
- Tests: 2 in `pk/tests`, 0 `#[test]` in Rust.  Untested: fq serve protocol, QOpt.args, store add/RANK, census classify, full_lines, explore.work, pipeline.evaluate, importers.

Not dead despite README: `slp.py`, `rigid.py` (via descend -> slp2), `mkseed` (transplant), `movegen` (band move).
Archive candidates (no importers): `census2.py`, `basin.py`, `channel.py`, `surgery.py`, `gadget_mc.py`, `beam.py`,
`hop.search` / `search_da`; `target-dev/` once `polish_trace.py`'s `--ident` build is in `target`.

## 4. External (10-11 scan; links in the jlevy/squares issues cited)

Polish and certify are at or beyond everything public (several contributors now run our fq / exactsolve).  Open ground is
constructors and proposals.  Not replicated by us:
- **SQUISH Mondrian v2** (itsnaka, #500, 9 records 10-11): pieces narrowed in their own rectangle before composing;
  interlocked pieces (176: corner block of Couzo s(127) cut out, s(5) reaching in); same-source double pieces (305 = two
  63-square pieces of their s(272)); seam repair as a stage.  Algorithms inferred from README wording; code not public.
- **Kevin Fang** (#484): AMS k²−k+1 two-wedge family; grow by cutting once through each wedge stack and adding a square
  to every line the cut crosses (273 -> 308, 307 -> 343 / 344), penalty squeeze.
- **Couzo** (#506): L-shaped border row added to a smaller packing, then squares removed, then search (380 from 343).
- **Ryan Xu** (#432, Substack): LLM program evolution (Haiku fleet, 128 generations, ~7.5k CPU-h + $125, 25 records);
  evolved inits at atan(1/2), atan(1/3), atan(2/3), staircases, rounded squares sharpening as the box shrinks.  Our
  generators use 38-45° only.
- **dostashev** (#501): V-shaped tilted band + IP-chosen Young-diagram corner blocks, soft-to-rigid, LP polish,
  canonicalisation (slide squares to corners, straighten loose ones).  "Growing bands by random search does not work above
  n ≈ 130: they jam."
- **BuddenPing / PingYou** (#503, #504): patches of one source (Xu N70) + upright grids; re-close the contact pattern at
  a new angle (exact constructions).
- Literature beyond lit-*.md: little.  FrontierCS problem 4 = this problem (arXiv 2512.15699; weak reference);
  soft-to-rigid (Nakajima) ≈ our corner-radius anneal (tried); Sparrow (arXiv 2509.13329) still the open nesting SOTA.

Ranked untried ideas (cost; cheap falsification): (1) Mondrian v2 narrowing + seam-only search (M; replicate the 11 "no"
n + #500's 9); (2) interlocked / same-source double pieces (S-M; rebuild 176, 305); (3) growth operators: wedge cut,
L-border (S; rebuild Fang 308/343/344 blind); (4) rational-slope tilt alphabet (S; first histogram frontier tilt angles,
zero compute); (5) patch-and-reclose (M; rebuild 207); (6) LLM program evolution scored on held-out rediscovery (L);
(7) V-band + canonicalisation (S); (8) GLS overlap weights in fq (M; battery grid rate + x110a crossings); (9) rectangle-
container continuation (S); (10) population annealing / splitting with per-cluster budgets (M).
