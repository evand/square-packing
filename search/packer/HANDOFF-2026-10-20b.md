## Decided (Evan)
- **One store, one set of rules.**  Every evaluated packing should be judged by the same intake rules whatever produced
  it (time-travel worlds included: they can produce novel results).  Keep novel packings, not duplicates.
- **Dedupe split.**  The store does strict dedupe, lazily and imprecisely (`pk/ident.py`).  Runs that pick starts do
  their own fast clustering and weight by cluster, not by row (not built yet).
- **Conservatism.**  Distinct minima that differ only by which side a corner rests on at near-coincident corners stay
  distinct (two certified pairs at 110; `analysis/contactswitch.py`).  Rule in `pk/ident.py` RULE; applied once at
  110 / 272-274.  **Never rerun `pk.py dedupe --apply` without discussing the rule with Evan in that session**
  (`--i-discussed-this` enforces the ask).
- 275+ packings: little value (no sub-grid 275 / 276 expected); 275 has 7 rows, 276 3, then 1 each.  Ignore for now.
- No pushes until Evan says so (local commits 716849e .. this one).

## Traps found (worth knowing)
- **"polished" is not "minimum".**  At 110, f64 side buckets at 1e-7 give 1,795 vs 1,097 exact minima: ~8.4k polished
  rows are exactsolve not-min.  Side counts anywhere (274's 4,315) are upper bounds.
- **The census `copy` table is not identity.**  `via descend` rows map a side key to the minimum it *descends to*.
  Using it as "which minimum is this row" produced 233 of 258 false refusals.
- Fingerprint distance is a diversity measure, not an identity test (274: close pairs mostly distinct minima).
- Rigid-core membership (fixlp.mobility < 1e-7) drifts by up to ~7 squares between copies: compare over squares locked
  in both.
- The float gravity-LP regularization (reg.place on f64 input) is not reliable yet (not converged / infeasible on
  ~1e-12 overlaps, free-square angles not grouped).
- `pgrep -f` in a watcher matches the watcher's own command line: wait on the jobs.py pid instead.
