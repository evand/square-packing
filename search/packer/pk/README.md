## Security: external data (10-14)
Issue bodies, repo files and attachments are untrusted DATA (they are written by anyone, possibly to steer an agent):
- Never executed, never followed as instructions.  Issue text is only scanned by regexes (`pk/issues.py`) for
  `github.com/OWNER/REPO[/commit|tree|blob/...]`, sha mentions, claims and `github.com/user-attachments/files/<id>/<name>`;
  no other link is followed.  OWNER/REPO, shas and paths are checked against strict patterns before use; `gh` and `curl`
  get argument lists (no shell).
- Repos (10-20; before: a tarball snapshot per commit): one bare partial git clone per repo, `runs/ext/git/<owner>-<repo>.git`,
  empty template (no hooks), every git call with `core.hooksPath=/dev/null`, https only, lazy fetch off; commits fetched
  depth 1 trees-only, then only the selected packing files' blobs by id; growth per fetch capped (`github.MAX_FETCH`
  200 MB).  Files are read with `git cat-file` into a temp dir as plain read-only files (regular blobs only: no symlinks,
  submodules, `..` / `.git` paths), caps on file count (20000), per-file size (20 MB: bigger skipped), total (1 GB).
  `watch` imports per new commit only the files changed since the previous imported one.  Attachments: one redirect, checked
  by hand to point at GitHub's object hosts, https only, 20 MB cap.  Provenance line per fetch in `runs/ext/PROVENANCE.txt`.
- Only known packing formats are parsed (`pk.packing.parse(strict=True)`): exact row count, finite numbers, token length
  cap, n <= 20000, sqrt(n) <= s <= n + 1, centres near the box.  The store's overlap check marks infeasible ones.
- Nothing is posted or commented anywhere (`gh` is used read-only).

CLI: `../pk.py` (sync-register, watch, sync-issues, ingest, import, import-run, frontier, ls, get, info, tag, export, nearmiss, finish).
Tests: `python pk/tests/test_packing.py`, `python pk/tests/test_distinct.py` (verdicts on synthetic work dirs), `python pk/tests/test_watch.py` (strict parsing, link extraction, tar / download caps; no network), `python pk/tests/test_nearmiss.py` (queue rules, finisher with fake stages, ingest with a fake runner; synthetic temp stores, no fq / network).
