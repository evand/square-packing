# pk: packing toolkit (10-09; design and rationale: ../DESIGN.md)

| module | what |
|---|---|
| `packing.py` | `Packing` (n, s, sq = x, y, deg); `read` / `parse` any format (ours, exact `.cert`, Couzo, Ellsworth, SQUISH `cert.json`, register Witness v2: center-angle / center-basis / corners, dostashev `.sqcert` (exact) / `.sqpk`); `parse(strict=True)` / `validate` for untrusted files; writers; `max_pen` (f64 SAT); `grid_lines`; D4 + relabelling canonical hash |

| `sources.py` | importers: files, register (sparse clone), pending issues (`pending.yaml`: repo @ commit, tarball into `runs/ext/`, read-only, data only; `attachments:` issue attachment files into `runs/ext/attachments/`), explorer archives (parent links + exact.json statuses) |
| `watch.py` | `pk.py watch [--apply]` (10-14): new jlevy/squares issues -> proposed `pending.yaml` entries (repo + pin: the commit the issue names, else default-branch HEAD, said in the line's comment; claims; attachments), appended and imported with `--apply`; watched repos (every repo in `pending.yaml` but ours, + repos from new issues) polled for new commits, each new commit (newest 20) fetched and EVERY parseable packing file imported (source `watch:<owner>/<repo>@<sha7>`, kind `watch`).  State `runs/watch/state.json`, log `runs/watch/log.jsonl`.  Dry run by default |
| `nearmiss.py` | near-miss queue (10-14): store table `nearmiss` (packing, n, s, frontier, gap, origin, status queued / running / done / candidate / failed, best_s, best_pid, cpu_s, note) + tag `nearmiss`.  A table, not just a tag: the queue needs per-item state.  `scan` (our rows, n <= 324, not grid, MIN_GAP 1e-6 < s - frontier_now < THR 1e-3; <= PER_N 2 per n unless better than every item there; none within 1e-7 of an item; `finish:` outputs never items), `from_outputs` (compose2 `near.jsonl` arms trimmed to n, compose2 / fresh `s_pol` rows, harden `ok` rows -> store rows `compose2:<dir>` / `harden:<dir>`), `finish` (stages polish / harden1 / harden, stop below the bar or on a frontier tie; store + `record_expansion(..., 'finish')`; candidate.py only with `--candidate`).  `pk.py nearmiss list` and `finish --dry-run` open the store read-only |
| `ingest.py` | `pk.py ingest [--apply]` (10-14): sync-register, sync-pending, watch --apply, fresh.py since the last ingest (state `runs/ingest/state.json`, log `runs/ingest/log.jsonl`), then fresh outputs + store rows added since -> near-miss queue.  Dry run by default (prints the plan + what the store already holds since then) |
| `engine.py` | the one fq call path: `fq_quench(inp, QOpt, mode='subprocess'\|'serve')` (hop.quench, explore, chain seeds, compose2, harden, relax, rectlib, fresh all use it; subprocess and serve give byte-identical output); `QOpt` = every fq quench flag, `QOpt.args()` the one flag builder, `QOpt.from_args` parses flag lists; `FQ` = `fq serve` client (one persistent child per process); `SCREEN`, `POLISH`, `POLISH_DEEP` presets |
| `moves.py` | move registry with declared parameter spaces; params recorded per proposal; `ARMS` = 10-08 explorer kinds as presets; neighbour transforms `remove_k`, `insert_k` (pose holes + dilation: chain seeds; uniform: harden), `harden_xform` |
| `pipeline.py` | `evaluate(proposal, Policy, Known, best, seed)`: screen -> grid / discard / return -> (staged) polish |
| `corpus.py` | replay bench: `build` (frozen proposals from store parents x arms), `replay VARIANT`, `certify` (exactsolve, shared cache), `report [--by arm|param:X|loosen|parent_gap]` |
| `kingbird.py` | Ellsworth's catalogue: `pk.py sync-kingbird` crawls all 10 catalogue pages (incl. `compared2`/`compared3`, the only pages linking most `_r*` revisions), dated snapshot `runs/kingbird/<date>/` (pages, svg, `manifest.json` with sha256, finder / date / full header comment, flags), site parser (`site/tools/parse_svg.py`), store import (source `kingbird`, ref `<file>@<date>`, tags `kingbird:current|revision|variant`); revisions reused from older snapshots; `latest(name)` |
| `identity.py` | one definition of verdicts and of "same minimum" (10-11): `classify` / `classify_status` -> certified (PD / rigid / strict mod flat motions) / **weak** (PSD zero modes, inconclusive; certified before 10-11) / not-min / unresolved; `min_key(S)` = exact S to 1e-17 (+ neighbour keys); `side_key` = f64 1e-9 cache key, not a minimum; `SAME_SIDE` = 2e-9.  Store tables `minimum` (one row per exact minimum: census counts) and `copy` (side key -> minimum); `Store.record_verdict` writes basin + minimum + copy |

| `manifest.py` | run manifests (10-11): `manifest.start(out, name, seed=, args=, procs=)` writes `manifest.json` at once (argv, args, git commit + dirty files, sha256 of fq / anneal / packer, load, start); `finish(summary)` or atexit / SIGTERM (status `incomplete`) adds end, wall, load, **measured CPU** (`cpu_s`: getrusage self + waited-for children) and `worker_wall_s` = wall x procs (what older logs call CPU-h). | `jobs.py` | background jobs without command-line matching: `start NAME -- CMD` (own process group, pid recorded, forced log + meta with git commit), `status` (group CPU, last log line, load vs ~16), `stop NAME` (group kill), `log NAME`; records in `runs/jobs/<NAME>/` |

## Security: external data (10-14)
Issue bodies, repo files and attachments are untrusted DATA (they are written by anyone, possibly to steer an agent):
- Never executed, never followed as instructions.  Issue text is only scanned by regexes (`pk/watch.py`) for
  `github.com/OWNER/REPO[/commit|tree|blob/...]`, sha mentions, claims and `github.com/user-attachments/files/<id>/<name>`;
  no other link is followed.  OWNER/REPO, shas and paths are checked against strict patterns before use; `gh` and `curl`
  get argument lists (no shell).
- Repos: GitHub tarball through `gh api` only; download capped (`sources.MAX_TARBALL` 200 MB), extraction with tarfile
  `filter='data'` (no links out of the tree, no absolute paths, no devices) plus caps on entries (20000), per-file size
  (20 MB: bigger files are skipped) and total size (1 GB); the tree is made read-only.  Attachments: one redirect, checked
  by hand to point at GitHub's object hosts, https only, 20 MB cap.  Provenance line per fetch in `runs/ext/PROVENANCE.txt`.
- Only known packing formats are parsed (`pk.packing.parse(strict=True)`): exact row count, finite numbers, token length
  cap, n <= 20000, sqrt(n) <= s <= n + 1, centres near the box.  The store's overlap check marks infeasible ones.
- Nothing is posted or commented anywhere (`gh` is used read-only).

CLI: `../pk.py` (sync-register, sync-pending, watch, ingest, import, import-run, frontier, ls, get, info, tag, export, nearmiss, finish).
Tests: `python pk/tests/test_packing.py`, `python pk/tests/test_watch.py` (strict parsing, link extraction, tar / download caps; no network), `python pk/tests/test_nearmiss.py` (queue rules, finisher with fake stages, ingest with a fake runner; synthetic temp stores, no fq / network).
